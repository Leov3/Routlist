## 1. Introducción

Routlis es un panel operativo para organizar audios, botones de reproducción, usuarios, categorías, correos transaccionales y otras funciones de trabajo diario.

Este manual está escrito para usuarios finales y administradores operativos.  
No describe funciones internas del backend ni herramientas de mantenimiento técnico.  
El objetivo es que cualquier usuario con acceso al panel pueda entender:

- qué puede hacer
- dónde encontrar cada función
- cómo interpretar la información que ve
- cómo resolver problemas comunes

## 2. Acceso al sistema

### 2.1 Inicio de sesión

1. Abre la pantalla de acceso.
2. Ingresa tu correo.
3. Ingresa tu contraseña.
4. Presiona el botón de acceso.

Si las credenciales son válidas, entrarás al panel principal o a la organización que tengas asignada.

### 2.2 Cierre de sesión

Usa el menú de usuario para cerrar sesión cuando termines tu trabajo, especialmente si compartes equipo o navegas desde una estación pública.

### 2.3 Sesión persistente

La sesión puede mantenerse activa durante más tiempo para evitar que tengas que iniciar sesión a cada momento.  
Si la sesión expira, vuelve a iniciar sesión normalmente.

### 2.4 Buenas prácticas de acceso

- No compartas credenciales.
- No uses contraseñas obvias.
- Verifica siempre que estás en la organización correcta antes de editar contenido.
- Si cambias de equipo, cierra sesión.

## 3. Estructura general de Routlis

Routlis está dividido en dos grandes zonas:

- zona de operación diaria
- zona de administración

### 3.1 Zona de operación

Aquí trabaja la mayoría de usuarios:

- `/board`
- pantallas de audios
- detalles de botones
- filtros y búsqueda

### 3.2 Zona de administración

Aquí se administran recursos del sistema:

- usuarios
- categorías
- botones
- audio
- correo
- organizaciones
- paneles de estadísticas

No todos los usuarios ven las mismas opciones.  
El acceso depende del rol.

## 4. Navegación principal

### 4.1 Sidebar

La barra lateral agrupa las áreas principales del sistema.

Puedes encontrar:

- Botonera
- Audio IA
- Llamadas
- Administración
- módulos de sistema

### 4.2 Encabezado

El encabezado superior muestra el título de la pantalla activa y acciones frecuentes como:

- recargar
- abrir configuración de cuenta
- cambiar tema

### 4.3 Organización activa

Si tu cuenta puede operar en más de una organización, confirma siempre cuál está activa antes de hacer cambios.

### 4.4 Reglas de navegación

- Usa la barra lateral para ir entre módulos.
- Usa el contenido de cada pantalla para operar.
- Evita abrir varias acciones simultáneas si afectan al mismo recurso.

## 5. Uso de la botonera

La botonera es la vista principal de trabajo y está pensada para reproducir audio de forma rápida.

### 5.1 Qué ves en la botonera

- botones de audio
- imagen o miniatura asociada
- texto del botón
- categorías
- favoritos
- recientes

### 5.2 Acciones básicas

- Buscar un audio.
- Filtrar por categoría.
- Marcar como favorito.
- Reproducir con un clic.
- Ver detalles con el menú de contexto.

### 5.3 Modo simple

El modo simple muestra una sola lista compacta.

Es útil cuando:

- quieres navegar rápido
- hay pocos elementos
- prefieres una vista limpia y directa

### 5.4 Modo de dos columnas

El modo de dos columnas permite trabajar en paralelo con dos conjuntos de filtros.

Es útil cuando:

- necesitas comparar grupos de botones
- quieres tener dos listas visibles
- manejas muchas categorías a la vez

### 5.5 Recomendaciones para operación

- Mantén los nombres cortos.
- Usa favoritos para accesos frecuentes.
- Si el botón no reproduce, revisa si el audio está disponible.
- Si el audio no se oye, verifica el volumen del navegador y del equipo.

## 6. Gestión de audios

### 6.1 Biblioteca

La biblioteca de audios contiene los archivos que luego se asignan a botones.

### 6.2 Qué puedes hacer

- subir nuevos audios
- revisar metadatos
- validar duración
- consultar nombre original
- buscar archivos existentes

### 6.3 Cuando conviene revisar un audio

- antes de crear un botón
- cuando el texto no corresponde al audio
- cuando el archivo parece duplicado
- cuando el audio no carga en la botonera

### 6.4 Buenas prácticas

- Usa nombres comprensibles.
- No subas duplicados si ya existe el mismo contenido.
- Revisa siempre que el audio corresponda con el botón final.

## 7. Gestión de botones

Los botones representan accesos visuales al contenido de audio.

### 7.1 Qué contiene un botón

- texto principal
- audio asociado
- imagen opcional
- categoría
- estado activo/inactivo
- favorito
- orden o secuencia

### 7.2 Crear un botón

1. Abre la pantalla de botones.
2. Completa los datos básicos.
3. Asocia el audio correcto.
4. Elige una categoría.
5. Guarda el registro.

### 7.3 Editar un botón

Puedes cambiar:

- el texto
- la imagen
- la categoría
- el orden
- el estado

### 7.4 Duplicar un botón

Duplicar sirve para crear una variante basada en un registro ya existente.

Se recomienda cuando:

- el contenido es parecido
- solo cambia una parte del texto
- necesitas conservar la estructura visual

### 7.5 Ver detalles

La ficha de detalle permite:

- ver la imagen en grande
- escuchar el audio
- copiar textos
- descargar recursos asociados

### 7.6 Consejos

- No dejes botones sin audio si deben usarse en producción.
- Revisa el texto antes de publicar.
- No mezcles categorías demasiado distintas en un mismo botón.

## 8. Gestión de categorías

Las categorías agrupan los botones y audios para ordenar la botonera.

### 8.1 Para qué sirven

- ordenar el contenido
- filtrar más rápido
- separar tipos de audio
- facilitar búsqueda y navegación

### 8.2 Crear categorías útiles

Buenas categorías suelen ser:

- cortas
- descriptivas
- consistentes
- fáciles de reconocer

### 8.3 Ejemplos de uso

- campañas
- atención
- soporte
- procesos internos
- avisos

### 8.4 Recomendación

No llenes el sistema con categorías demasiado específicas.  
Es mejor tener pocas categorías bien definidas que muchas categorías confusas.

## 9. Gestión de usuarios y organizaciones

### 9.1 Usuarios

La pantalla de usuarios permite administrar quién entra al sistema.

#### Acciones comunes

- crear usuarios
- editar datos básicos
- asignar rol
- activar o desactivar cuenta
- eliminar cuenta cuando corresponda

#### Qué revisar antes de guardar

- correo correcto
- rol correcto
- nombre visible correcto
- estado correcto

### 9.2 Invitaciones

Las invitaciones sirven para dar acceso a nuevas personas sin crear la cuenta manualmente en todos los casos.

Cuando el sistema lo permita, también puedes registrar el nombre de la persona invitada para que coincida con los correos y la UI.

### 9.3 Organizaciones

Si tu cuenta puede operar con más de una organización:

- verifica la organización activa
- cambia de organización solo cuando sea necesario
- no edites datos en la organización equivocada

### 9.4 Buenas prácticas organizacionales

- Trabaja siempre con la organización correcta.
- Evita duplicar contenido entre organizaciones sin criterio.
- Verifica que los cambios realmente quedaron guardados.

## 10. Correo transaccional

El sistema de correo está pensado para notificaciones automáticas y pruebas manuales.

### 10.1 SMTP

La pantalla SMTP permite configurar el envío global del correo.

Campos comunes:

- nombre del remitente
- correo del remitente
- host
- puerto
- usuario
- contraseña
- reply-to
- seguridad
- estado activo

### 10.2 Pruebas

La pantalla de pruebas sirve para validar que el correo realmente sale con la configuración actual.

Úsala después de:

- cambiar credenciales
- cambiar de proveedor
- modificar el remitente
- actualizar plantillas

### 10.3 Plantillas

Las plantillas son el contenido que recibe el usuario final.

Pueden incluir:

- HTML
- texto plano
- CSS extra
- variables dinámicas

#### Variables comunes

- `{{user_name}}`
- `{{organization_name}}`
- `{{platform_name}}`
- `{{login_url}}`
- `{{reset_url}}`
- `{{invite_url}}`
- `{{invite_code}}`
- `{{inviteeName}}`
- `{{inviterName}}`
- `{{audio_title}}`
- `{{license_expiration}}`
- `{{storage_used}}`

#### Cuándo usar variables

- en saludos personalizados
- en invitaciones
- en recuperación de contraseña
- en alertas del sistema
- en notificaciones operativas

### 10.4 Eventos

Los eventos son acciones del sistema que disparan correos automáticos.

Ejemplos:

- usuario creado
- invitación enviada
- recuperación de contraseña
- alerta por almacenamiento alto
- narrativa lista
- audio procesado
- error de procesamiento
- licencia próxima a vencer

### 10.5 Historial

El historial permite revisar:

- envíos exitosos
- envíos fallidos
- respuestas SMTP
- errores de entrega

### 10.6 Cola

La cola está preparada para mensajes pendientes, fallidos o en reintento.

### 10.7 Buenas prácticas de correo

- prueba antes de activar una plantilla
- revisa variables antes de publicar
- evita cambios grandes sin validar
- guarda una copia de seguridad del HTML si vas a editar correos importantes

## 11. Panel de estadísticas

El panel de estadísticas resume el estado general del sistema.

### 11.1 Qué muestra

- salud del backend
- salud de la base de datos
- uso de disco
- actividad de correo
- métricas de audios
- métricas de botones
- invitaciones pendientes
- estado de branding

### 11.2 Para qué sirve

- detectar problemas tempranos
- revisar si un cambio afectó el sistema
- ver la carga real de uso
- tener una lectura rápida del estado general

## 12. Reproducción y detalles

### 12.1 Ficha de detalle

La ficha de detalle de un botón sirve para revisar información más precisa sin salir de la botonera.

### 12.2 Importación masiva

Si trabajas con lotes, el sistema puede mostrar una revisión previa antes de crear elementos.

### 12.3 Recomendación

Revisa siempre la importación antes de confirmar, sobre todo si hay archivos nuevos o duplicados.

## 13. Buenas prácticas operativas

- Trabaja siempre en la organización correcta.
- No edites contenido durante una importación sin terminar.
- No cambies varias configuraciones críticas al mismo tiempo.
- Revisa plantillas de correo antes de activarlas.
- Usa nombres consistentes en botones, audios y categorías.
- Si algo falló, revisa el historial antes de repetir la acción.

## 14. Guía por rol

## 14.1 ADMIN

El rol `ADMIN` administra la operación diaria de su organización.

### Lo que normalmente puede hacer

- gestionar usuarios de su organización
- crear y editar botones
- organizar audios y categorías
- revisar correos transaccionales
- operar invitaciones
- consultar estadísticas de uso

### Tareas típicas de un ADMIN

1. Revisar la botonera del equipo.
2. Subir o actualizar audios.
3. Crear botones nuevos para contenido operativo.
4. Corregir textos o imágenes.
5. Revisar correos de prueba o plantillas.
6. Verificar usuarios activos y pendientes de invitación.

### Qué debe revisar con frecuencia

- contenido duplicado
- audios mal asignados
- botones inactivos por error
- correos que fallan
- cambios en la organización activa

### Errores comunes de ADMIN

- editar en la organización equivocada
- dejar un botón sin audio
- usar una plantilla de correo antigua
- no revisar el estado activo antes de publicar

## 14.2 SUPERVISOR

El rol `SUPERVISOR` está pensado para operación y seguimiento.

### Qué puede hacer

- revisar la botonera
- usar favoritos y búsquedas
- consultar detalles de botones
- validar que el contenido esté disponible
- seguir el historial de actividad
- comprobar el estado de audios

### Tareas típicas de un SUPERVISOR

1. Verificar que los audios correctos estén listos.
2. Confirmar que los botones están visibles.
3. Usar la botonera durante la operación diaria.
4. Detectar errores de contenido antes de que lleguen al usuario final.
5. Reportar incidencias de forma clara.

### Qué debe revisar con frecuencia

- nombres de botones
- estado de audios
- favoritos usados por el equipo
- categorías mal agrupadas

### Errores comunes de SUPERVISOR

- asumir que un botón incorrecto es temporal
- no reportar audios faltantes
- usar un filtro equivocado y pensar que el contenido desapareció

## 14.3 OPERATOR

El rol `OPERATOR` es el rol más operativo del día a día.

### Qué puede hacer

- buscar audios
- reproducir botones
- usar favoritos y recientes
- navegar por categorías
- ver detalles cuando tenga acceso

### Tareas típicas de un OPERATOR

1. Abrir la botonera.
2. Buscar el audio o botón necesario.
3. Reproducirlo.
4. Usar favoritos para accesos frecuentes.
5. Avisar si un botón no responde o está mal etiquetado.

### Qué debe revisar con frecuencia

- si el audio correcto aparece en pantalla
- si el botón se reproduce sin error
- si la categoría ayuda a encontrar el contenido

### Errores comunes de OPERATOR

- usar demasiados filtros a la vez
- confundir favoritos con recientes
- pensar que un audio no existe cuando solo está en otra categoría

## 15. Preguntas frecuentes

### 15.1 No veo un botón

Verifica:

- el filtro activo
- la categoría seleccionada
- si el botón está inactivo
- si estás en la organización correcta

### 15.2 El audio no suena

Revisa:

- volumen del navegador
- volumen del equipo
- si la sesión sigue activa
- si el archivo existe

### 15.3 No aparece una plantilla de correo

Comprueba:

- que la plantilla esté activa
- que el módulo de correo esté disponible en tu rol
- que estés usando la ruta correcta

### 15.4 Un correo no llegó

Revisa:

- la configuración SMTP
- el historial
- la cola
- el contenido de la plantilla

### 15.5 Un cambio no se guardó

Verifica:

- que presionaste guardar
- que no hubo error de red
- que el formulario no tenga campos obligatorios incompletos

## 16. Solución de problemas

### 16.1 El panel carga lento

Posibles causas:

- conexión lenta
- demasiados elementos cargados
- navegador con muchas pestañas

### 16.2 Un archivo no se reproduce

Posibles causas:

- audio corrupto
- ruta incorrecta
- archivo no asociado al botón

### 16.3 Un usuario no ve lo mismo que yo

Posibles causas:

- rol distinto
- permisos distintos
- organización activa distinta

### 16.4 Qué hacer antes de pedir ayuda

1. Anota el módulo.
2. Anota la acción exacta.
3. Toma captura si hace falta.
4. Verifica tu rol y organización.
5. Revisa si el error ocurre siempre o solo una vez.

- nuevas secciones
- capturas
- flujos paso a paso
